## 2. Method

Two independent meters, matched by timestamp.

### Windows process meter — `mem-sample.ps1`

`C:\Users\sonny\AppData\Local\Temp\st-test\mem-sample.ps1` appends one row per
30 s for a pid:

```
timestamp,WS,Private,GPU-shared
2026-09-11T15:27:00.0000000Z,<WS>,<Private>,<GPU-shared or empty>
```

Usage (header comment in the script has the full text):

```powershell
powershell -ExecutionPolicy Bypass -File C:\Users\sonny\AppData\Local\Temp\st-test\mem-sample.ps1 -ProcessId <pid>
```

- `WS` = `Get-Process.WorkingSet64`, in MB.
- `Private` = `Get-Process.PrivateMemorySize64`, in MB.
- `GPU-shared` = sum of `\GPU Process Memory(*)\Shared Usage` over the GPU
  instances whose name contains the pid, in MB; empty when the counter set is
  unavailable (the query is optional and never fatal).

### Client meter — `DEBUG=st:mem`

`packages/app/src/debug/mem-log.ts` (B.2 step 1) writes one JSON line to stderr
immediately at startup and every 30 s:

```
st:mem {"at":…,"rss":…,"heapUsed":…,"heapTotal":…,"external":…,"replicaBytes":…,"surfaces":…}
```

All sizes are bytes. The process fields come from `process.memoryUsage()`;
`replicaBytes` is Σ `stReadProp(id,'stats').replicaBytes` over the mounted
Panes (the stat added by B.2 step 2). Until that field lands in the native
module the sum reads 0 and the `surfaces` count still shows how many Panes the
sum covered. `stReadProp(id,'stats')` also carries `gaps`, `resyncs` and
`snapshots` from Part A, useful to confirm the run did not Resync.

### Run sequence

1. Release test Server on 7172 (`--no-idle-exit`, `RUST_LOG=info`) against the
   Windows Client; the packaged/debug or `bun` Client under test.
2. Launch the Client with `DEBUG=st:*` (the `st-test.ps1 launch` driver already
   sets it) and capture stderr to a log.
3. Start the sampler for the Client pid.
4. Walk the scenarios below; note the wall-clock start of each phase so the
   `st:mem` lines and CSV rows line up.
